Aviation Analytics Dashboard

57,392 Clean Records Analyzed
90K+ Raw Records Processed
8 Interactive Dashboard Views

Project Overview

This project analyzed the NTSB Aviation Accident Database to identify where aviation risk actually concentrates — by aircraft make, flight phase, weather condition, and flight purpose — providing evidence-based guidance for stakeholders evaluating entry into the aviation business.

Challenge

The raw dataset had 90,348 records across 31 columns spanning decades of incidents, but it was inconsistent: inconsistent data types, missing coordinates, injury counts buried in free-text fields, and heavy gaps in older records.

Solution

Cleaned and structured the dataset in Python — standardizing columns, parsing dates, extracting injury counts from text with regex, and handling missing data deliberately — down to a reliable 57,392-row dataset, then built an interactive Tableau dashboard so non-technical stakeholders could explore the findings themselves.

Key Findings

  • Accident frequency has trended downward since peaking in the early 1980s
  • Most accidents occur in good visual weather (VMC), not poor instrument conditions (IMC) — pointing to pilot complacency as a bigger risk factor than weather itself
  • Certain manufacturers, including Boeing and Bell, show disproportionately high fatal-injury counts
  • Personal/private flights account for the largest share of accidents by a wide margin
  • Injury severity is heavily right-skewed — most accidents result in zero or minimal injuries

Technologies Used

Python Pandas NumPy Seaborn / Matplotlib Tableau

Recommendations Delivered

Prioritize pilot training and decision-making standards over weather-driven safety assumptions, treat personal/private aviation as the highest-risk segment for insurance and safety planning, and apply model-level due diligence when selecting aircraft for a fleet.

Movie Recommendation Engine

100K+ Ratings Analyzed
9,742 Movies in Catalog
12.25% Accuracy Gain Over Baseline

Project Overview

Built a personalized movie recommendation system trained on the MovieLens dataset — over 100,000 ratings from 610 users across nearly 10,000 movies. The system predicts how a user would rate a movie they haven't seen yet, then surfaces their top 5 personalized picks.

Challenge

User-movie rating data is extremely sparse — the vast majority of possible user-movie pairs have no rating at all, and over 60% of movies in the catalog have fewer than 5 ratings. A good model has to find meaningful patterns in mostly empty data.

Solution

Implemented and compared five recommendation algorithms — from neighborhood-based approaches (KNN) to matrix factorization (SVD, NMF) — using cross-validated hyperparameter tuning to find the best-performing model for this dataset.

Key Findings

  • Matrix factorization (SVD) outperformed similarity-based approaches, learning hidden patterns in user taste rather than just matching similar users or movies
  • The final model predicts ratings within roughly 0.86 stars of the actual rating on average
  • Predictions are most reliable for typical, mid-range ratings and less reliable at the extremes — movies a user loves or hates intensely are harder to predict precisely

Technologies Used

Python Surprise Pandas / NumPy Matplotlib / Seaborn

Customer Churn Prediction

84.5% ROC-AUC Score
77.8% Recall — Churners Caught
7,043 Customers Analyzed

Project Overview

Built an end-to-end machine learning pipeline to predict customer churn for a telecommunications company. Starting from raw data and ending with a deployable prediction system, the project follows the full CRISP-DM data science methodology — from business understanding through to model deployment and business recommendations.

Challenge

The dataset had a significant class imbalance — only 26.5% of customers had churned — making standard models biased toward predicting "no churn." Missing values, incorrect data types, and the need to engineer meaningful features added further complexity.

Solution

Applied SMOTE (Synthetic Minority Oversampling) to balance the training data, engineered 4 new features (AvgMonthlySpend, StreamingServices, OnlineServices, LongTermContract), and tuned the decision threshold to 0.4 to maximize recall — catching as many at-risk customers as possible before they leave.

Key Findings

  • Month-to-month contract customers churn at 42.7% vs only 2.8% for two-year contracts
  • Fiber optic internet customers churn at 41.9% — likely a pricing or service quality issue
  • Electronic check payment method has the highest churn rate at 45.3%
  • Senior citizens churn at 41.7% vs 23.6% for non-seniors
  • New customers (tenure < 3 months) are the highest risk group
  • 2,064 high-risk customers identified representing $139,131 in monthly revenue at risk

Methodology

  • Exploratory Data Analysis — distributions, correlations, churn patterns by segment
  • Data preparation — binary encoding, one-hot encoding, StandardScaler normalization
  • Feature engineering — created 4 new meaningful business features
  • Trained & compared 5 models: Logistic Regression, Decision Tree, Random Forest, KNN, XGBoost
  • Applied SMOTE oversampling and threshold tuning (0.4) to handle class imbalance
  • 5-fold cross-validation for reliable and unbiased performance estimation
  • Deployed reusable prediction function with High / Medium / Low risk segmentation

Model Performance

  • Final Model: Random Forest + SMOTE @ Threshold 0.4
  • Recall: 77.79% — catches 78 out of every 100 churners
  • ROC-AUC: 84.49% — strong discrimination power
  • F1 Score: 63.37% — good balance for imbalanced data
  • Stability: Cross-val std dev < 2.2% — model is consistent and reliable

Technologies Used

Python Scikit-learn XGBoost imbalanced-learn (SMOTE) Pandas / NumPy Matplotlib / Seaborn Tableau Joblib Jupyter Notebook

Business Impact

The model flags 2,064 high-risk customers monthly for proactive retention outreach. If just 30% of identified churners are retained through targeted campaigns, the company saves approximately $28,000/month — or $336,000 annually — in otherwise lost revenue. A full Tableau dashboard and CSV reports were delivered alongside the model for business team use.

MwanaSpoty — Jersey E-commerce Platform

Live Deployed on Vercel + Render
Next.js Frontend Framework
Full Stack Frontend, API, Database, Admin

Project Overview

MwanaSpoty is a full-stack e-commerce platform for football jerseys and custom apparel, aimed at fans across Kenya and East Africa. Customers can browse jerseys by league, customize kits with printed names, numbers, and competition badges, and check out — while admins manage products, orders, and customers through a full dashboard with real data visualizations.

Challenge

Building a genuinely complete e-commerce platform end-to-end — not just a storefront, but real authentication, a working checkout flow with product customization and live pricing, an admin panel with proper access control (customers' personalization requests are only visible to fulfillment staff, not exposed in the general order list), and real analytics — then deploying all of it live.

Solution

Built the frontend in Next.js with a component-based design system (custom color palette and typography), a Node/Express REST API backed by PostgreSQL via Prisma, JWT-based auth with role-based access control, and Cloudinary for multi-image product uploads. Deployed the frontend to Vercel and the API to Render, with environment variables centralizing configuration between local development and production.

Key Features

  • Browse jerseys by league, search, categories, and a Best Sellers page driven by real sales data
  • Jersey customization: size, custom name/number printing, and competition badges, with live price calculation
  • JWT authentication, persistent cart/wishlist, and full order history
  • Admin dashboard: full product CRUD with multi-image upload, order management with status updates, customer list, and analytics (best-sellers, best-leagues, customer segments, low-stock alerts, 7-day sales trend) visualized with Recharts
  • Order fulfillment access control — customization details (names/numbers to print) are excluded from the main admin order list and only shown in a dedicated single-order detail view

Technologies Used

Next.js (App Router) React Tailwind CSS Node.js / Express PostgreSQL (Neon) Prisma ORM Cloudinary Recharts JWT / bcrypt

What's Next

Planned additions include real M-Pesa payment integration (Daraja API), a password reset flow, and customer reviews on products.
